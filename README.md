# 秋の関西 2026

2026/11/29–12/6 的關西賞楓行程（京都、嵐山、大阪、奈良）。給自己和媽媽在旅途中用的手機網頁，可以「加到主畫面」像 App 一樣打開，有網路時自動更新，沒網路也能看。

**網址：** https://roserosejump.github.io/kansai-walks/

純 HTML / CSS / JavaScript，沒有框架、沒有打包工具，不用 `npm install`。

---

## 手機怎麼用

**加到主畫面**
- iPhone：用 **Safari** 開網址 → 分享按鈕 → 加入主畫面
- Android：用 **Chrome** 開網址 → 右上角選單 → 安裝應用程式（或加到主畫面）

**出發前請先做（很重要）**
1. 在**有網路**時把 8 天的行程各點開一次。中文字型是「看過的字才會下載」，沒看過的字離線時會變成系統字型（不影響閱讀，只是字體不同）。
2. 預約編號**不在**這個網站裡，畫面上會顯示「LINE 記事本」，請到 LINE 記事本找對應的代碼。
3. 想調整字的大小：下方「資訊」分頁 → 字體大小。

## 五個分頁

| 分頁 | 內容 |
|---|---|
| 首頁 | 清水寺插圖、出發倒數、旅行期間的「現在／下一站」、今天入口、航班資訊（登機證造型） |
| 行程 | 搜尋框、8 天大卡片（今天那張整張楓紅色）；點進去是當天的時間軸 |
| 清單 | 待辦事項與購物清單，可以勾選（記在手機上） |
| 資訊 | 字體大小、天氣、日幣換算 |
| 緊急 | 迷路回旅館、警察、救護車、駐大阪辦事處、旅館清單；每張卡片附一句日文，可以直接拿給日本人看 |

**單日頁的時間軸**
- 收合：一個行程一列，只顯示時間與一句話標題；預設全部收合，一個螢幕看完一天
- 點開：小卡橫跨整列展開，由上到下是：完整名稱、標籤、資訊表（地點、營業、交通、費用、預約）、重點框（取消、一定、最晚…）、備註、導航按鈕
- 每天第一列是「從飯店出發」、最後一列是「回飯店」（最後一天是「回家」）

## 資料怎麼改

行程資料**全部直接在 `data/` 裡編輯**，不再用 Google Sheet 轉檔。

| 檔案 | 內容 |
|---|---|
| `data/day1.json` … `day8.json` | 每天的行程（順序就是畫面上的順序） |
| `data/checklist.json` | 待辦與購物清單 |
| `data/config.json` | 標題、天數、日期、天氣城市、匯率參考值 |
| `data/short-titles.json` | 每個行程的「一句話短標題」（吃飯加早餐／午餐／晚餐） |
| `data/day-themes.json` | 每天一句話主題 |
| `data/day-cities.json` | 每天經過的城市（依順序） |
| `data/access.json` | 每個行程「怎麼去」的交通說明 |
| `data/flights.json` | 航班：航空公司、托運與手提行李、餐點、報到截止 |

行程之間靠每個行程的 **`id`**（例如 `3-7`）對應：短標題、交通說明都用 `id` 當 key。`id` 是固定寫在檔案裡的名字，**新增行程請取一個沒用過的新 `id`**，不要重複使用，其他檔案的對應就不會亂。怎麼改、怎麼新增，見 [HOW-TO.md](HOW-TO.md)。

> `scripts/sheet-to-json.mjs` 是舊的 Sheet 轉檔腳本，**已停用**。它會用 Sheet 的舊資料整個覆蓋 `data/`，所以現在必須加 `--force` 才會執行。除非你確定要重新匯入，否則不要跑。

其餘資料來源：
- 天氣：Open-Meteo（出發前約 7 天才查得到預報）
- 匯率：open.er-api.com，查不到時用 `config.json` 的參考值

## 隱私與預約編號

這個 repo 是**公開**的，所以：

- **預約編號、訂單號碼不放進網站。** 資料裡一律遮成「●●●」，畫面上顯示成「LINE 記事本」小標籤；真正的代碼存在 LINE 記事本。
- `private/`（舊轉檔時拆出來的預約編號）和 `sheet-export/`（舊的 Sheet 匯出 CSV，含編號）**永遠不要 commit**，已寫在 `.gitignore`。
- push 之前建議檢查一次有沒有敏感資料被追蹤：
  ```
  git ls-files private sheet-export     # 應該沒有任何輸出
  ```
- 行程日期、航班、旅館名稱屬於公開資訊；公開前請自己確認可以接受。

## 本機開發

不需要安裝套件，用任何靜態伺服器打開專案資料夾即可（不能直接雙擊 `index.html`，瀏覽器會擋住本地檔案讀取）：

```
python3 -m http.server 8765      # 然後打開 http://127.0.0.1:8765/
# 或
npx --yes serve .
```

資料怎麼改，見 [HOW-TO.md](HOW-TO.md)。

## 部署與更新（GitHub Pages）

- 設定：repo → Settings → Pages → Source 選 *Deploy from a branch*，Branch 選 `main`、資料夾 `/ (root)`
- 更新：`git push` 之後，GitHub 約 1–3 分鐘建置，再加上瀏覽器快取約 10 分鐘，才會在手機上看到新版
- **改了檔案卻看到舊畫面**：到 `sw.js` 與 `index.html` 把快取版本一起 +1（目前是 `kansai-walks-v4`，兩處 `CACHE_NAME` 與 `SW_CACHE_NAME` 要相同），再 push

## 技術說明

- **時間一律用日本時間**（`Asia/Tokyo`）判斷「今天」與「現在／下一站」；出發倒數則以台灣時間 2026/11/29 09:00 起飛為準
- **離線策略**（`sw.js`）：網站檔案「網路優先，最多等 3 秒，逾時就用快取」；Google Fonts 用「先用快取、背景更新」
- **字級**：用百分比縮放根字體，所有 rem 尺寸一起放大，四段可調（記在手機的 localStorage）
- **無障礙**：觸控區 ≥ 44px、內文對比 ≥ 4.5:1、支援「減少動態效果」、按鈕都用真正的 `<button>`
